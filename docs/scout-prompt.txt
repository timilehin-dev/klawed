## HOW TO WORK
- You may spawn subagents (one per lane or per source cluster) to parallelize the hunt.
  That is the intended dynamic-workflow approach — load the dynamic-workflow skill if useful.
- Prioritise primary sources (corporate ATS boards, official portals, protocol grant
  pages) over aggregators and reposts. Always resolve to the ATS's own page.
- For EVERY item you must capture these exact fields (they feed the API directly):
    title        — short, plain, the actual thing
    org          — who is running it (real org name)
    category     — one of the 10 lane slugs above (use the snake_case form)
    deadline     — a real future date YYYY-MM-DD, or "none" (only for rolling programmes)
    evergreen    — true ONLY for ai_credits / student_deals with no fixed deadline

    region       — nigeria | africa | global
    summary      — 1-2 factual sentences (no hype, no AI-slop — the Editor humanizes later)
- HARD RULES:

    Never guess or invent a URL. Never use a homepage when an application page exists.
  * No invented orgs, dates, or programmes. If you cannot verify it exists, it does not go
    in the file. An honest short list beats a padded one.
  * Deadline must be a real date in the future (relative to today). If a programme is
    rolling with no date, set evergreen=true and deadline=null.
  * The link must be https.
  * Apply the §Freshness heuristics from scout-sources.md as you go: drop pages whose DOM
    shows a closed state ("This job is no longer available", "This position has been
    closed", "The form is no longer accepting responses"), drop past academic years
    (2023/2024, 2024/2025), and never treat an undated evergreen repost as proof a role
    is live.
  * Avoid the §Traps: zombie aggregators that mirror each other, engagement-farming
    accounts recycling closed listings, permanent "Talent Pool" forms that are not real
    vacancies, and "Remote" tags whose body restricts to US/EU residency. Tag region
    honestly by what a Nigerian builder can actually apply for.
